# Spec: anonymous workspace, optional sign-in

**Status:** Shipped — slices 1 and 2. `chronos.anon.owner`, `OptionalAuthRoute`,
and the claim-on-sign-in re-key are live. Slice 3 (sample decision) is
superseded — see "Sample decision" below.

Today a public-beta visitor must create an account, name a workspace, set a goal,
and attach a source before Chronos does the thing Chronos is for. This spec
removes the account from that list and makes sign-in what it should be: how you
keep your work, not how you start it.

---

## Principle

Local-first is the default, not the fallback. Signing in adds durability and
sharing; it does not unlock the product.

---

## Why this is cheap

The data layer already supports it. Three mechanisms exist today:

| Mechanism | Where | What it gives us |
|---|---|---|
| `remote: null` | `WorkspaceService` constructor | Local-only mode is already first-class (unit tests run this way) |
| `byOwner[ownerId]` | `LocalWorkspaceStore` | All local state hangs off one key — claiming is a re-key, not a migration |
| "empty cloud backfilled from local" | `WorkspaceService.load` | Once local data sits under a real user id, sign-in pushes it to Supabase with no new code |

The work is a route change, an anonymous id, a re-key on sign-in, and honest UI.

---

## Anonymous identity

A v4 uuid in `localStorage` under `chronos.anon.owner`, created on first visit to
`/workspace`. It is an **owner key, not a user** — never sent to Supabase, never
written to `profiles`, never used in RLS.

Anonymous mode constructs `WorkspaceService` with `remote: null`. This is the
security boundary and it is structural, not a conditional: with no remote there
is no code path that can write anonymous data to the cloud.

---

## Claiming work on sign-in

The only step with data-loss risk, so it is specified precisely.

On a transition from anonymous to authenticated:

1. Read the bundle at `byOwner[anonId]`.
2. If `byOwner[realUserId]` is **absent or empty**, move the bundle to that key.
3. If it is **non-empty**, the account already has work. Do **not** merge —
   keep the account's data, leave the anonymous bundle in place, and tell the
   user their local work was kept separate. Silent merge risks interleaving two
   decision histories, which corrupts the one thing Chronos promises to remember.
4. Clear `chronos.anon.owner` only after a successful move.
5. Normal load then backfills the cloud from local, using existing code.

Re-keying is idempotent and non-destructive: nothing is deleted, only moved.

---

## What anonymous users do not get

Enumerated, because a blank surface is worse than an honest one:

- **Sharing / members** — needs real identities. Surface reads "Sign in to
  share", not an empty list.
- **Cross-device resume** — clearing site data loses the workspace. Must be said
  plainly in the UI, not buried.
- **Cloud backup** — nothing leaves the browser.

Everything else — goals, knowledge, notes, simulations, futures, collapse,
re-branch, memory, plan steps — works identically, because it already runs
against the local store.

---

## Route change, and the test it contradicts

`ProtectedRoute` currently redirects `/workspace` to `/login`. Workspace routes
move to an `OptionalAuthRoute` that renders regardless; `/workspace/settings`
stays protected while it owns sharing.

`decision-workspace.spec.ts` asserts **"without e2e flag, workspace still
requires login"**. This spec deliberately inverts that assertion. It is called
out here rather than quietly edited, because a test named *requires login* is
exactly the kind of thing that should not change without someone deciding it
did. The replacement asserts the new contract: an anonymous visitor reaches the
workspace, and the sign-in affordance is present.

No security property is lost — anonymous data never reaches Supabase, so there
is nothing for RLS to protect.

## Sample decision

> **Superseded.** Retired by
> `docs/superpowers/specs/2026-08-01-decision-first-entry-design.md` ("The
> seeded sample decision is retired"): decision-first entry fuses
> goal-setting and running into one submit, which closed the only window in
> which the sample was ever reachable. `sampleDecision.ts` and the sample
> banner UI are deleted. Kept below for history — do not re-implement
> against this section.

A new anonymous workspace is empty, which is the same cold-start problem one
step later. Seed one realistic worked example — objective, ranked futures, a
collapse, a logged outcome — that a visitor can open and explore immediately.

Rules that keep it honest:

- Flagged `is_sample: true` on the simulation record, visibly labelled in the UI.
- Never counted in beta-checklist progress, learning memory, or activity.
- One click to remove, and removed automatically on the first real simulation.
- Generated by the **real engine** at seed time, not hand-written fixtures —
  a fake ranking in a product whose entire claim is deterministic ranking would
  be the worst possible thing to ship.

## Slices

1. **Anonymous workspace** — anon id, `remote: null`, route change, sign-in
   affordance, replaced E2E assertion.
2. **Claim on sign-in** — the re-key, including the non-empty-account case.
3. **Sample decision** — engine-generated, labelled, removable. Superseded,
   see "Sample decision" above.

Ship in that order. Each is independently revertable, and slice 1 is useful
alone.

---

## Boundaries

**Always:** anonymous mode constructs with `remote: null`; the durability
limitation is stated in the UI, not implied.
**Ask first:** merging an anonymous bundle into an account that already has
work; anything that writes an anonymous id to Supabase.
**Never:** an anonymous id in `profiles`, RLS, or any cloud table; a sample
decision that is not visibly labelled; a sample ranking not produced by the
engine.

---

## Success criteria

1. A visitor with no account reaches `/workspace` and completes objective →
   futures → collapse without signing in.
2. Nothing anonymous appears in Supabase — verified against the live project,
   not assumed.
3. Signing in with a fresh account claims the local work; signing in with an
   account that already has work keeps both, loses neither.
4. The sample decision is labelled, excluded from progress, and its ranking
   matches what the engine produces for that objective. Superseded, see
   "Sample decision" above — there is no sample decision to satisfy this
   against.
5. `tsc`, `biome ci`, unit and E2E green.
